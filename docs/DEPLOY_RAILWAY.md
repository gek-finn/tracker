# Развёртывание на Railway

Инструкция для онлайн-демонстрации Task Tracker: Railway предоставляет
HTTPS, домен и постоянный том (volume) для SQLite.

> Важно: локальная рабочая база `tasks.db` в Railway **не загружается**.
> Онлайн-версия стартует с пустой базой на собственном томе.

## 1. Предварительные требования

- Аккаунт GitHub с опубликованным репозиторием проекта
  (см. [GITHUB_PUBLISH.md](GITHUB_PUBLISH.md)).
- Аккаунт [Railway](https://railway.app/) (бесплатного стартового баланса
  хватает для учебной демонстрации).

## 2. Создание сервиса

1. Открыть <https://railway.app/new> → **Deploy from GitHub repo** →
   выбрать репозиторий `tracker`.
2. Railway определит Python по `requirements.txt` и запустит команду из
   `Procfile`:
   ```
   web: gunicorn --workers 1 --threads 4 --timeout 90 --bind 0.0.0.0:$PORT app:app
   ```
   Порт берётся из переменной `PORT`, которую предоставляет платформа.

## 3. Постоянный том для SQLite

Файловая система контейнера пересоздаётся при каждом деплое, поэтому база
обязана лежать на volume:

1. В сервисе: **Settings → Volumes → New Volume**, точка монтирования
   `/data`.
2. Переменная окружения (Variables):
   ```
   TASK_TRACKER_DB=/data/tasks.db
   ```
3. База и схема создадутся автоматически при первом старте (`init_db`).

## 4. Переменные окружения (Variables)

| Переменная | Значение | Комментарий |
|---|---|---|
| `TRACKER_ENV` | `production` | полный режим защиты: всё закрыто паролем; задайте явно (среда Railway распознаётся и автоматически) |
| `TASK_TRACKER_DB` | `/data/tasks.db` | база на постоянном томе |
| `TASK_TRACKER_SECRET` | длинная случайная строка | `python -c "import secrets; print(secrets.token_hex(32))"` |
| `TRACKER_ADMIN_PASSWORD` | ваш пароль | доступ ко ВСЕМУ интерфейсу, кроме `/healthz` (логин `admin`) |
| `TASK_TRACKER_DEBUG` | не задавать / `0` | debug в production принудительно выключен |

`TRACKER_HTTPS=1` и `TRACKER_PROXY_FIX=1` в production включаются
автоматически — задавать не нужно.

**Fail closed:** без `TRACKER_ADMIN_PASSWORD` или `TASK_TRACKER_SECRET`
приложение не запустится (в Deploy Logs будет понятная ошибка) — это
защита от случайного публичного деплоя без пароля.

После изменения переменных Railway сам пересоберёт сервис.

## 5. Проверка

- **Healthcheck**: открыть `https://<домен>/healthz` — ожидается
  `{"ok": true, "db": "ok"}` без авторизации (данных не раскрывает).
  В настройках сервиса можно указать Healthcheck Path = `/healthz`.
- Главная страница по HTTPS: браузер спросит логин/пароль
  (`admin` / `TRACKER_ADMIN_PASSWORD`); без них любой запрос к страницам,
  API и экспорту возвращает 401.
- После входа доступны все разделы — просмотр, канбан, экспорт.

## 6. Один экземпляр — обязательно

SQLite в этом проекте рассчитан на один процесс. В настройках сервиса
оставьте **1 реплику** (`Procfile` уже запускает одного gunicorn-воркера).
Несколько реплик = несколько независимых баз на разных томах.

## 7. Сохранность базы при повторном деплое

- Том `/data` не пересоздаётся при деплое — база сохраняется.
- «Redeploy» и обновления кода данных не трогают.
- Опасные операции: удаление **сервиса** или **тома** — стирают базу.
  Перед удалением скачайте копию (см. ниже).

## 8. Резервные копии онлайн-базы

В терминале сервиса (Railway → сервис → вкладка **Terminal**):

```
python backup.py backup
```

Копия появится в `backups/` на томе. Чтобы скачать: Railway → Volume →
открыть файлы тома и скачать `backups/tasks_backup_...db`.
Восстановление — там же:

```
python backup.py restore backups/tasks_backup_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.db --yes
```

(восстановление заменяет базу; gunicorn перезапустится командой
`touch app.py` или через Redeploy).

## 9. Обновление приложения

```
git pull / push новых коммитов в GitHub → Railway задеплоит сам
```

Данные на томе при этом не меняются.

## Возможные проблемы

| Симптом | Причина и решение |
|---|---|
| 502/503 сразу после старта | смотрите Deploy Logs; проверьте, что `PORT` используется из env (уже в Procfile) |
| `sqlite3.OperationalError: unable to open database file` | том не смонтирован или неверный `TASK_TRACKER_DB` |
| Изменения задач пропадают после деплоя | база лежит не на томе: проверьте `TASK_TRACKER_DB=/data/tasks.db` |
| Сессии слетают после рестарта | не задан `TASK_TRACKER_SECRET` |
