# Резервное копирование и восстановление

Модуль `backup.py` работает с базой через **SQLite Backup API** — копия
согласована даже при работающем приложении. Перед восстановлением
проверяется целостность и автоматически создаётся страховочная копия.

## Создание копии

Способ 1 — двойной клик по **`бэкап.bat`** (Windows).

Способ 2 — команда:

```
.venv\Scripts\python backup.py backup                 # Windows
.venv/bin/python backup.py backup                     # Linux/macOS
```

Дополнительные параметры:

```
python backup.py backup --db ПУТЬ_К_БАЗЕ --out КАТАЛОГ_ДЛЯ_КОПИЙ
```

Результат: файл `backups/tasks_backup_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.db`,
прошедший проверку целостности (`PRAGMA integrity_check`).

## Восстановление

Восстановление **заменяет текущую базу**. Требования:

1. Приложение остановлено (иначе команда откажется с понятной ошибкой).
2. Подтверждение: команда спросит `Type YES to continue`
   (или флаг `--yes` для скриптов).

```
.venv\Scripts\python backup.py restore backups\tasks_backup_2026-11-11_10-00-00.db
```

Что происходит при восстановлении:

1. Проверяется целостность указанной копии (повреждённая — отказ).
2. Текущая база автоматически копируется в `backups/pre_restore/…`
   (страховочная копия «до восстановления»).
3. Замена выполняется атомарно; старые `-wal`/`-shm` файлы удаляются.

Если что-то пошло не так — восстановите страховочную копию из
`backups/pre_restore/` той же командой `restore`.

## На Railway

Через терминал сервиса (см. [DEPLOY_RAILWAY.md](DEPLOY_RAILWAY.md), раздел 8):
том `/data` переживает деплои, копии лежат рядом с базой, скачиваются
через интерфейс Railway.

## Проверка копий вручную

```
python -c "import sqlite3; print(sqlite3.connect('ФАЙЛ').execute('PRAGMA integrity_check').fetchone()[0])"
```

Ожидаемый вывод: `ok`.
